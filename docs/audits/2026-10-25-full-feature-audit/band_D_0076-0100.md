## 3. Top findings, ranked by payoff

**F1. The production game runs with an uncalibrated set of vote-tilting layers.** VERIFIED
- **Evidence:**
  - `deploy/orwell-env-defaults.sh` turns on CAMPAIGNS (0085/0086/0096), TRAJECTORIES, TRIGGERS, JURY_HOUSE, VOTE_DEDUCTION, TRAITORS_FURY, DEAL_DEPTH and others.
  - The calibration gates (`tests/property/juryReach*`, `calibrationGradient*`, `tests/uat/*`) never enable them. The only flag any of them sets is `ShowrunnerReweight`.
  - No CI job sets these envs (grep of `.github/workflows`). `deploy/smoke.sh:51-55` boots with the shipped flags, but only for one turn.
  - The design doc admits as much: `docs/design/2026-07-21-moonshot-refactor-synthesis.md:141-151`.
- **What the owner would notice:** the "playing actively beats coasting" balance (active 20% vs passive 7%) was measured on a game nobody plays. The deployed game, with campaigns, nemesis, jury grudges and vote deduction all stacking on the jury and eviction votes, could be much harsher on the player (or tilted some other way) and nothing would flag it.
- **Fix size:** M. Add a juryReach/gradient shard that runs with the deploy flag set and asserts the `EARNED_WINS` band. If it goes red, re-tune.
- **Depends on:** every deploy-on flag here, plus 0110 and #1790 from other bands.

**F2. Mood, current-read and rivalry cues are built but almost never reach the narrator (0084, 0088, 0096).** VERIFIED for the code path; LIKELY for the under-call rate
- **Evidence:**
  - `mood` (`GameSessionAdapter.ts:2164`), `currentRead` (`:2202`) and `rivalry` (`:2207`) exist only in the `npcVoice` tool result.
  - The narrator prompt advertises them only as fields of `npcVoice` (`momentPrompts.ts:480,493`).
  - The push path `presentKnowledgeForPrompt` (`:10629-10636`) already calls `npcVoice` for every houseguest in the room, then throws away everything except `knows` and `suspects`.
  - Nothing on the FE calls `npcVoice` automatically.
  - The 2026-07-21 audit measured `npcVoice` called 0 times in 24 turns (`moonshot-refactor-synthesis.md:22`). Voice itself has since been pushed on the roster; these three cues were not.
- **What a player would notice:** houseguests' moods, their warming or cooling toward you, and a nemesis's personal edge stay invisible in the narration, even though the engine computes all three every turn.
- **Fix size:** S. Add `mood`, `currentRead` and `rivalry` to the existing `PresentKnowledgeView` (they are already Vault-safe words). Changing the prompt changes the golden request digest; per the moonshot doc the golden fixture was removed in #1765, so confirm whether a re-record is still owed.

**F3. `confront` (0094) does nothing in any deployed game.** VERIFIED
- **Evidence:**
  - `ORWELL_GOSSIP_CONSEQUENCE` defaults OFF (`:6302-6306`). It is absent from deploy defaults, `featureFlags.ts`, `/health` and the `setBehavioralFlags` dial (`registry.ts:92`).
  - `setGossipConsequenceEnabled` has no non-test caller.
  - With the flag off, `confront` returns `{landed:true}` and has no fold (`:6327`). Even with the flag on, a *landed* confront has no positive effect; only the misfire branch folds.
  - The narrator is told to call it (`momentPrompts.ts:504-510`).
  - Unlike confide/expose/trade, there is no FE back-fill belt for confront or `accuseTie` (`agent_loop.py:8617-8643`).
- **What a player would notice:** confronting someone over a garbled rumor is always safe. The "you acted on bad intel and it blew up" moment never happens.
- **Fix size:** S. Add the flag to the deploy defaults, `featureFlags.ts` and the God-Mode dial. Calibration is unaffected, because the lever is player-channel only.

**F4. Campaigns only move the eviction vote, and "the scramble" has no mechanical effect (0085).** VERIFIED
- **Evidence:**
  - `campaignTiltFor` (`:7592-7608`) counts only `goal === "evict"`.
  - Its single consumer is `voteChoice` (`liveSeason.ts:1560`). No campaign term exists in nomination, veto-use or replacement code.
  - The spec says campaigns tilt "nominations, the veto, replacement noms" and that "a 'protect' campaign lowers them" (`0085-npc-campaigns-and-the-scramble.md:121-125`). The README repeats "tilting the seeded noms/veto/votes".
  - The pivot to `protect` (`campaigns.ts:275`) happens, but changes nothing. The nemesis code (`:7712-7716`) can also overwrite a nominated nemesis's protect campaign with evict-the-player; harmless today only because protect is inert.
- **What a player would notice:** a nominee scrambling to save themselves never changes a single vote, and NPC HOHs never nominate because of a campaign. The fight over the vote is all narration and no mechanics.
- **Fix size:** M. Wiring nominations, veto and protect into the tilt is calibration-load-bearing, so it must be done together with F1's flags-on calibration shard. Otherwise, correct the README and spec to "eviction-vote only".

**F5. Half of 0095 never runs, and `accuseTie` has two correctness slips.** VERIFIED
- **Evidence:**
  - `ORWELL_TIE_REVEAL` is in neither the deploy defaults nor the dial. The overhear pathway `advanceTieReveal` (`:6209`) returns early every tick.
  - `accuseTie` applies the fold to `livingIds()` (`:6272`), meaning every living houseguest including those in other rooms or asleep. The comment says "who was present".
  - Once `maxExposuresPerSeason: 2` is spent (`tieRevealConstants.ts:43`), a correct accusation of a still-sealed real tie returns `{landed:false}` (`:6258`). The narrator then plays it as a miss, so the engine tells the player something false.
  - The docstring says a miss is "recorded as an ordinary social scene". The code records nothing; the FE auto-record belt covers this.
- **What a player would notice:** pre-show ties never leak out on their own. The third correct accusation in a season is "wrong" even when it is right, and houseguests who weren't there react as if they saw it.
- **Fix size:** S for the presence filter and an honest result after the cap. M to enable the overhear pathway, which needs a calibration re-run because it folds betrayal shock.

**F6. One God-Mode toggle leaks across all users (0092).** VERIFIED
- **Evidence:** `setBehavioralFlags` sets `secretPacing` and `seededTieSurfacing` via static process-wide overrides (`:7022-7023`). The admin tool text promises "for this sandbox" (`registry.ts:92`).
- **What the owner would notice:** toggling secret pacing for one game silently flips it for every concurrent user. This is not a Vault leak, but it goes against the cross-user isolation guarantee.
- **Fix size:** S. Make the override per-instance, like campaigns.

**F7. Trigger eruptions treat the player as an eyewitness wherever they are (0091).** VERIFIED (intentional per comment, but in tension with ADR 0009 and 0076/0077)
- **Evidence:** `witnessSet: [PLAYER, ...]` is set unconditionally (`:7509`) because `validateEvent` requires the player in any non-hidden event.
- **What a player would notice:** they "witnessed" a blow-up in a room they weren't in. That is a small "people must make sense" break.
- **Fix size:** S to M. Record it as hidden plus a house-wide announcement pathway, or gate it on co-presence.

**F8. Minor issues**
- 0086's own-ballot lean is suppressed whenever the voter owns *any* active campaign on that target, including non-evict ones, because there is no goal check (`:7604`). VERIFIED, Low.
- SUSPECTED, not traced: a model-called or belt-called `exposeSecret`/`tradeSecret`/`confront` is not in `_RECORD_TOOLS` (`agent_loop.py:2432`), so `_auto_record_scene` can also fire on the same turn. That could fold the same social act twice.

## 4. Conflicts

- **Overlapping vote tilts:** 0085 campaign tilt, 0086 own-ballot lean, 0096 nemesis campaign, 0043 blocs and 0039 deals all feed the same `voteChoice` score (`liveSeason.ts:1555-1564`). Separately, 0100 grudge, 0110 deduction and #1790 fury all feed the jury lean. Each is bounded on its own; with all of them on together (the deploy) the combination is unmeasured (F1). Up to 4 concurrent campaigns sum without a cap on the total (`CAMPAIGN.base 0.25 × maxConcurrent 4`), though in practice they are small.
- **0096 vs 0085 adaptation:** the nemesis re-aim can override a self-protect pivot (`:7712-7716`).
- **0098 vs the frozen standing principle** ("a player input must never modulate a seeded variance"). This is correctly held inert. The PO ledger (`PO-REVIEW-LEDGER.md:119-120`) still says Frozen/confirm-Defer, while the README says REOPENED. The owner needs to reconcile the two.
- **0091 player-always-witness vs 0076/0077/ADR 0009 presence truth** (F7).
