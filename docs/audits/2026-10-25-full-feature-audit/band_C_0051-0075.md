## 2. Top findings (ranked by payoff)

### F1. 0070 off-screen texture is written but never read (wasted LLM spend, promised richness never arrives). VERIFIED
- **Write side:** `recordOffscreenSceneTexture` only does `this.textureOverrides.set(eventId, sanitized)` (GameSessionAdapter.ts:10960). It does not change the event.
- **Readers:** `textureOverrides` has exactly one reader, `getOffscreenSceneSkeletons` (GameSessionAdapter.ts:10933). That method feeds the same FE driver back. The other references are only serialize/restore (3480, 3831).
- **Delivery paths the spec names (0070.md:45-46, 61, 71) cannot carry it:**
  - Overhears get `s.event.content` at tick time (orchestrator.ts:~772), before the async write-back lands.
  - Gossip diffuses `rumorFrom(initiator, partner, type)`, a template, not the event content (orchestrator.ts:866).
  - Retrospective, confessional and producerVault renders read the event record, not the overrides.
- **Cost:** the FE fans out up to `MAX_SCENES_PER_TICK = 6` utility-LLM calls per model `advanceGame` (orwell_offscreen_texture.py:38, kicked at tool_implementations.py:5219-5220).
- **Tests:** the BDD step for "reaches the player" only asserts a sentinel is *absent* (offscreen_texture.steps.ts:138-145). The "carries voiced texture" check re-reads the skeleton (lines 79-88). Neither proves the texture reaches anyone.
- **Secondary gap (VERIFIED):** the kick fires only from `do_advance_game`, not from the per-turn off-screen tick that every committed mutation runs. Ticks from social turns are never enriched, and the skeleton index is transient and overwritten each tick (GameSessionAdapter.ts:10914-10916).
- **What the owner would notice:** token spend with zero visible effect. Overheard scenes and gossip stay thin template labels, which is the exact problem 0070 was meant to fix.
- **Fix:** M. Options:
  - Read `textureOverrides` where overhear/gossip/retrospective content is rendered. Timing matters: the texture lands after the tick, so it would have to apply at later retellings or reads.
  - Or turn off the driver until there is a consumer.
- **Dependency:** gossip (0038) and overhear (0049). Must keep the 0031 leak sweep and the expressiveNonCollapse byte-identity intact.

### F2. 0066 time/sleep: the FE turns it on, but it silently goes dark after an engine-only restart. LIKELY (each link verified; the restart scenario is reasoned)
- **How it is turned on:**
  - The engine default is OFF: GameSessionAdapter.ts:6868-6872 reads `ORWELL_TIME_OF_DAY`.
  - Deploy does not set that variable (deploy/orwell-env-defaults.sh has no `ORWELL_TIME_OF_DAY`).
  - The FE default is ON (`"time_of_day_enabled": True`, frontend/src/settings.py:35). The FE pushes it through the admin `setTimeOfDay` tool, which sets a **process-global, in-memory** static override that resets to `null` on engine restart (GameSessionAdapter.ts:6861-6866).
- **Why it does not come back:**
  - The FE re-apply `_apply_persisted_time_of_day_once` latches `_TIME_OF_DAY_APPLIED = True` once per FE process (frontend/routes/chat_helpers.py:78, 93-108). Nothing ever resets the latch except tests.
  - The boot apply runs only at FE startup (frontend/app.py:1135-1165), and is skipped entirely in multiuser mode.
  - The engine unit has `Restart=on-failure` (deploy/systemd/orwell-engine.service:41). The FE unit only `Wants=` the engine and does not restart with it.
- **Effect:** after an engine crash or OOM restart, with the FE still up, the season continues with the clock, Nightfall, rest cue, day-break night gate and sleep penalty all OFF until the FE itself restarts. The ops scripts (update/doctor) restart both units, so they don't trigger it.
- **What a player would notice:** mid-season, the time of day, night gating and "staying up late" consequences just stop, with no error shown.
- **Fix:** S. Either:
  - add `ORWELL_TIME_OF_DAY=1` to `orwell-env-defaults.sh`, so the engine default matches the FE default and survives restarts; or
  - drop the latch when an engine call fails or the engine is seen to restart.
- **Doc drift:** README row 0066 and CLAUDE.md both say "Opt-in (`ORWELL_TIME_OF_DAY`, default off)". In practice it is on by default for every FE-driven game.

### F3. 0072 gateway cannot play the game: no decision submit, no advance, no tools; the BDD scenario is vacuous. VERIFIED
- **What the code does:** `_call_player_turn` makes only read calls plus one narration LLM call, then the 0055-style `fold_gateway_turn` (frontend/gateway/handler.py:85-200). The gateway never calls `submitDecision` or `advanceGame` (grep finds no submit/advance in frontend/gateway/).
- **What the spec promises:** "a text reply submits it through the existing decision path" (0072.md:59-60).
- **The test:** the BDD steps assert only that handler.py contains the strings "numbered list" and "orwell_engine", plus an `assert.ok(true)` (multi_platform_gateway.steps.ts:186-221). The comment "including submitDecision if pending" is false.
- **Risk:** a Telegram player is shown numbered options, replies, and nothing binds. The tool-less model may narrate a closed-set outcome that never happened. That is a narrated-but-not-recorded action, an anti-sycophancy concern, and the web pre-emission outcome guard is not applied here.
- **Minor bug (VERIFIED):** the history loader collects the *oldest* 5 assistant messages from the last 10, then reverses them, so the model sees prior replies in reverse order (handler.py:262-285).
- **What a player would notice:** on Telegram the game never moves forward; picks are ignored.
- **Fix:** M-L. Either route gateway turns through the agent loop or the decision path, or narrow the spec to "chat-only companion".
- **Mitigation:** flagged off unless `TELEGRAM_BOT_TOKEN` is set, so payoff is Med.

- README 0066 says time-of-day is "default off". The FE default is ON (see F2).

## 3. Conflicts
- **0070 vs 0038/0049:** 0070 assumes gossip and overhear carry event prose. Gossip uses a template (`rumorFrom`), and overhear captures content before the texture exists. The 0070 design and the propagation model are incompatible as built.
- **0066 vs the calibration spine / golden replay:** the engine default is kept OFF on purpose, so the seeded sims and golden replay stay byte-identical. The FE default ON makes live play differ from every engine-side gate. That is intended, but it is why the restart latch in F2 matters: the engine alone falls back to OFF.
- **0072 vs 0065/0023 ("never narrate unrecorded"):** the gateway narrates beats it cannot commit, and it has none of the web's pre-emission outcome guard.

## 4. Doc drift (brief)
- Two specs share the number 0065 (`0065-cast-prewarm` and `0065-llm-engine-sync-spine`). The sync spine has no `.feature` file.
- README/CLAUDE.md describe 0066 as opt-in/default-off. In practice the FE turns it on.
- README describes 0059 tie surfacing as default OFF. Deploy turns it on.
- 0070 README/spec claim "scenes that reach the player carry voiced texture". That path does not exist (F1).
- 0072 README says "Built". The decision-degradation clause is not implemented (F3).
- No real-time/watcher drift found in 0064/0066 specs or code. `GameWatcher`/`SystemClock` appear only in 0031, the ledger, and runtime.ts/LogicalClock.ts comments.
- No band write-back is missing the McpServer dispatch: `recordCastProfile`, `preSeedCast`, `recordWorldSnapshot`, `recordImageBeat`, `recordOffscreenSceneTexture`, `turnIn` and `confide` all have requireShape and callTool cases.
- The only new beats in this band are `day-break`, which is in `INERT_BEATS` (liveSeason.ts:145), and `self-eviction`, which is terminal, so it is correctly not inert.
