Product owner, 2026-11-15: worry about "the short list problem across the whole product". Rule: nothing is dealt from a teeny list; everything is as close to unbounded as the offline floor allows, and the live writer authors from the game's own facts.

Scanned-site tables are generated by `ci/short_list_inventory.py` from `ci/short_list_scan.py` (the scanner the CI guard `ci/check_short_lists.py` runs) over src/ TypeScript, frontend Python and frontend/static/js. Comments and docstrings are not scanned: only string literals a model or a player can receive. Numbers only; no play text. Class 1 = a string list under 40 items feeding a random, hash or modulo pick. Class 2 = "e.g./for example/such as" inside a string, or a closed menu. Each marker counts once. The roughly 435 raw "e.g." hits on the card are almost all code comments.

## The guard

`ci/check_short_lists.py` (scanner `ci/short_list_scan.py`, allowlist `ci/short_list_allowlist.json`), run by `npm run ci:fast`; its planted-failure test is `frontend/tests/test_short_list_guard.py`.

What it fails on:
- a string list that is dealt from (random pick, hash or modulo index, `Math.floor(rng * length)`, sample, shuffle, `among`), of ANY length, with no allowlist entry; an entry for a list of 40 or more, or for an ORW-511 list, also needs a written live-authoring decision;
- a new example line ("e.g.", "for example", "such as") or closed menu inside a string, including three or more quoted sample lines in a row with no marker word;
- an allowlist entry whose ceiling is above the real count (stale): the PR that fixes a site lowers or deletes its entry. An entry marked `transitional` (waiting on a named PR) is exempt, so PRs 2840 and 2843 merge clean in either order.

How a list is tied to a deal: to its own binding, not its name. A local list is checked inside its enclosing block; a module-level list in its own file and in the files that import it. One-hop aliases (`const full = POOL[kind]`) are followed. A look-alike name elsewhere does not count.

It finds: lists wrapped in a call (`widen([...])`), object tables (`POOL[kind]`, one hit per row), Python dict tables, inline lists dealt where they stand, and tables dealt through an alias.

Known limits: lists built from variables, spreads or `+`; lists returned from functions; property lists reached through another object (`J.lines`); aliasing of more than three hops; prompts in files that are not TS, Python or JS. A quoted sample under three lines slips through unless it is a spoken line of four or more words ending in ? or ! (single or double quotes, short or long, comma, "or", slash or no separator, even when it wraps across string literals; tested on the pre-#2866 moment prompt samples).

PR 2840's `poolGuard508.test.ts` and its allowlist are folded into this guard: every site its allowlist names is an entry here, so that test and file should be deleted when 2840 merges (on the merged tree it fails on new composed component lists and on a look-alike `names` list that this guard no longer confuses).

Every ORW-511 allowlist entry carries its own reviewed reason (one per site for text, a decision per list).
